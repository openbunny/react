Each `<component>.json` holds the markup that the original component rendered for the cases in `parity/definitions.tsx`. The file has one field, `cases`, a list of `name` and `html` pairs.

The markup was captured once with `renderToStaticMarkup` from the original components. No command in this package regenerates the fixtures, because the original components are not part of this package. A deliberate markup change to a package component, such as `Plate` rendering a `<picture>`, edits the affected fixture in the same commit as the component change. A new case in `parity/definitions.tsx` needs a fixture entry captured from the original component outside this package. Without one, `just parity` fails for that case.

A case with an `adoption` entry renders the package component with those extra props. They are the props a consumer passes to reproduce the original markup, because the package defaults are neutral. `just parity` also asserts that the default render differs from the fixture for such a case, so an adoption entry that no longer matters fails.
